## 二、怎么玩（3 分钟走完一局）

```
校园 → 选任务 → 登记数量 → 看核算 → 确认领取 → 攒成长值 → 浇水让树长大 → 攒够目标结算
```

| 步骤 | 你会看到什么 |
|---|---|
| 1. 校园 | 4 个入口：林荫步道 / 教学楼 / 食堂 / 进入花园 |
| 2. 任务 | 6 条日常 + 2 条活动任务，每条标了预计减排和金币 |
| 3. 登记 | 点「去完成」→ 弹出数量调节（默认值可改）→ 预计减排实时算给你看 |
| 4. 核算 | **计算情景**面板：减方式 / 活动量 / 基准因子 / 实际因子 / 公式 |
| 5. 领取 | 碳账本只读增加，成长值 = 减排量 × 10，金币 +N |
| 6. 花园 | 选植物 → 浇水（消耗 10 成长值，+10 成长）→ 跨阶段 |
| 7. 结算 | 3 天结束或达到 9.0 kg → 结算页 |

**一天有 4 点精力**，每条任务消耗 1 点。精力用完点「结束今天」。**6 条任务只能做 4 条**——这是设计上的取舍。

成长值     = floor(减排量 / 0.1)   ← 文档 P7：每 0.1 kg = 1 点

## 四、我替你做的 7 个设计判断（可推翻）

文档里没定义的地方，我按"能玩"来选了。**这些是我拍的板，不是你定的**，你不同意可以直接改 `data.js`：

1. **一局 = 3 天 + 目标 9.0 kg。** 文档没有"一局"的概念，只有连续的日记。但竞赛要 3 分钟收尾，必须有一个能结束的东西。
2. **加了「精力」约束（4 点/天）。** 否则玩家会把 6 条任务全做完，没有取舍；有了精力，就必须选"高减排还是多金币"。
3. **成长值是"池"，浇水把池灌进指定植物。** 这样"浇水"这个动作才有意义，而且玩家要决定先养哪一株。
4. **金币与成长值分工**：金币买盲盒/种子（游戏侧消费），成长值只用于让植物长大（由减排换算）。
5. **花瓣来自「盛放」采摘**，作为交换货币。原图只写了"花瓣/3枚"，没说从哪来——我把它接在采摘上，让"养到盛放"有回报。
6. **好友是 NPC 模拟**（小林同学 / 草莓奶盖 / 设计小王），可参观、可交换，不联网。
7. **碳账本绝对只读**：盲盒、交换、参观只会动金币和成长值。这条在代码里是分开的两个对象，不是同一个数加加减减。

## 六、部署到云服务器

纯静态，任何静态服务器都行。

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /var/www/cscampus;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    gzip on;
    gzip_types text/css application/javascript image/svg+xml;
}
```

```bash
scp -r web/* user@your-server:/var/www/cscampus/
```

**注意**：如果要装到手机主屏（PWA）或做 APK，必须走 **HTTPS**，否则浏览器不给安装权限。

## 九、校园行走地图（星露谷式）

**入口**：底部第一个 Tab「校园」。

| 操作 | 方式 |
|---|---|
| 移动 | 左下角拖虚拟摇杆 / 键盘 WASD 或方向键 |
| 进门 | 走到建筑门口，标记变绿并出现「轻点进入」，轻点它 |
| 去哪里 | 三食堂 / 四教 / 图书馆 / 南区宿舍 / 思源广场 五个点 |

### 技术实现

| 项 | 做法 |
|---|---|
| 世界坐标系 | 直接用原图 `1392×1130` 像素，渲染时统一放大 **2.2 倍** |
| 镜头 | 跟随玩家并夹在世界边界内，`lerp` 平滑 |
| 碰撞 | `assets/collide.png`（原图 1/2 分辨率，**白=可走、黑=阻挡**），逐点采样 |
| 水面 | 按 HSV 自动提取（色相 188–216、饱和 >0.42、蓝远大于红），占 8.1% |
| 建筑 | 18 个手工框，运行时把门点自动吸附到最近的可行走位置 |
| 移动 | 分轴判定 → 撞墙时沿墙滑动，不会卡死 |
| 角色 | 4 张立绘（正面/走/左/右），走路时上下轻微起伏，脚下有影子 |

### 已验证

- 镜头跟随、边界夹取、角色渲染、门点高亮、"轻点进入"提示 —— 均截图确认
- 进门后任务列表按地点过滤（「教学楼」只出 3 条本地任务）
- 出生点落在水面/建筑里时会自动吸附到地面（`freeSpot`）

### 已知限制（这是平面图的固有问题）

1. **没有遮挡关系**：整张地图是一张图片，人物永远画在最上层，走到树后面时会被树冠"穿过去"。要真正解决，需要把树、建筑拆成分层素材做 Y 轴排序。
2. **向上走用侧面朝向**：素材只有正面/左/右三向，没有背面，所以向上移动时保持侧面朝向，避免"倒着走"的怪感。
3. **地图边缘是硬的**：走到世界边界会被夹住，没有"走出校园"的过渡。
4. 放大 2.2 倍后画面偏软（原图只有 1392×1130）。

## 十、更新：真实路径 + 八方向动作（v2）

> **第九节的碰撞做法已废弃**，以下为准。

### 1. 路径改为按标注图提取

你提供的 `游戏地图中的人物移动路径.jpg`（1144×928）里，可走区域用青色高亮标出。直接按色提取：

```
H 118–178 · S > 0.14 · V > 0.78 · G ≥ R  →  青色高亮
收紧 3px → 缩放到 696×565 → assets/collide.png
```

- 覆盖率 10.2%，**和你的标注逐像素对齐**（做过叠加校验）
- 好处：路网、广场、桥面全对；不再是我早期那套"水+建筑框"的近似
- 代价：人物被严格限制在路面内，不能上草地——这正是"沿路走"的要求

### 2. 动作帧拼合

素材是 8 个文件，每个 `4352×544` = **8 帧 × 544 画格**，共 64 帧。

| 处理 | 说明 |
|---|---|
| 抠背景 | 从四边 flood fill，吃掉白底与投影；再补一刀去接近纯白的残留 |
| 帧内缩 | 左右各缩 14px，避免相邻帧的手臂串进来 |
| 缩放 | 0.28 → 单格 160×160，脚底对齐 |
| 拼合 | 8×8 图集 `hero8.png`（1280×1280，1.4 MB） |
| 收边 | 每格四周 12px 清空，彻底去掉跨帧残留 |

### 3. ⚠️ 素材命名与内容是反的

实测：

| 文件名 | 实际内容 |
|---|---|
| `上.png` | **正面**（看得到脸） |
| `下.png` | **背影**（看得到书包） |

即命名与内容差 180°。按运动方向映射时做了反向：

```
运动向下 → 上.png      运动向上 → 下.png
运动右下 → 左上.png    运动左上 → 右下.png
运动左下 → 右上.png    运动右上 → 左下.png
运动向左 → 左.png      运动向右 → 向右.png
```

**如果以后重做素材，请统一成"文件名 = 角色面朝的方向"。**

### 4. 动画与朝向

| 项 | 值 |
|---|---|
| 方向判定 | `atan2(dy, dx)` 取 8 个 45° 扇区 |
| 帧率 | 11 fps，8 帧循环 |
| 静止 | 回到第 0 帧 |
| 绘制 | 关闭插值（`imageSmoothingEnabled = false`），像素保持硬边 |
| 尺寸 | 160×160 屏幕像素，脚底对齐坐标点 |

### 5. 开发用参数（方便你自己验）

```
?at=teach      出生在四教门口
?move=r|d|u|rd 强制朝该方向持续走
?demo=1        预置花园数据
```

### 6. 仍然存在的限制

1. **没有遮挡**：人物永远画在最上层，经过地图上的标签/树时会盖住它们。
2. **左右向立绘偏正面**：AI 生成时左右方向区分度不高，横着走看起来仍像正面。要改善需要重新生成更强的侧视帧。
3. 地图放大 2.2 倍，画面偏软。
