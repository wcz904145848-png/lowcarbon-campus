# Collab —— 两个 AI 的工作台

> 这个目录**不在 `Assets/` 里**，Unity 不会导入它，可以放心放 markdown、线框图、CSV。

## 三个角色

| 角色 | 干什么 | 写盘范围 |
|---|---|---|
| **DSH（我）** | C# 代码、场景、预制体、构建、编译门、测试、git 提交 | `Assets/_Project/`、`Collab/20_Contract/`、`to-gpt/`、日志 |
| **Codex（设计端）** | 玩法、数值、关卡、UI、文案、美术提示词 | `Assets/GameData/`、`10_GDD/`、`30_Art/`、`from-gpt/` |
| **你** | 一句话派活 + 最终决策 | 任何地方 |

两个 agent 都能直接读写这个目录，所以**没有"复制粘贴"这一步**——但也因此多了一条铁律，见下面第三条。

> 注意区分两个界面：
> - **Codex（工作区 agent）** 能读写磁盘 → 走 `AGENTS.md`，自动生效，不用贴提示词。
> - **普通对话（chat）** 看不到磁盘 → 需要手动贴提示词 + 上传截图。**评审和头脑风暴用它更合适**，它不受工程约束，敢泼冷水。

## 一轮协作（五步，其中只有第 2 步需要你动手）

1. 我在 `to-gpt/` 写任务卡，`status: open`。
2. 你对 Codex 说一句：**「读 AGENTS.md，处理 to-gpt 里 status: open 的任务卡」**。
3. Codex 读契约 → 写 `from-gpt/T-00x-answer.md` → 把卡片改成 `status: done`。
4. 你说**「T-001 回收了」**。我校验 → 实现 → 跑 Unity 编译门 → git 提交。
5. 结论进 `50_DECISIONS.md`，我记 `60_LOG.md`。

**不再需要你把 300 行回答复制粘贴回来。** 第 2 步从"贴全文"变成"一句话"。

## 三条铁律

1. **契约是唯一真相。** 字段名、场景名、事件名只认 `20_Contract/contract.json`（版本号在文件内 `contractVersion`）。出现同义词就是退回，不是抠字眼——两个模型各自发明 `carbonPoint` / `carbonSaving`，三周后工程拼不上。
2. **写盘按目录切权。** 见上表。不共享写权限，因为冲突在 Unity 里表现为资产损坏，不是文本 diff。
3. **提交只由我发起。** 谁都能改文件，但 `git commit` 只有我跑。否则交叉提交会让「谁在什么时候改坏了什么」永远查不清。

## 并发时怎么不打架

- Codex 写 `Assets/GameData/*.json` 时，我不动同一个文件——我读它、校验它、报错给它。
- 我改代码和场景时，Codex 不碰 `Assets/_Project/`。
- 如果**必须**改同一个文件：先跟我说，我让出，改完我重新读。
- 卡住的时候看 `git status`。不干净就说明有人正在写。
