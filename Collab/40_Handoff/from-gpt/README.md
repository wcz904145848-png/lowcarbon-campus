# from-gpt —— 设计端交付物

**由 Codex 直接写**，不再由你手动保存。命名：`T-00x-answer.md`

```
T-001-answer.md
```

## 一份合格的交付物长什么样

```markdown
---
type: answer
target: T-001
contractVersion: 0.1.1
---
## 1. …
## 2. …
## 契约变更提案（如有）
```

## 我会怎么处理它

1. 读原文（不是摘要——我要看它自己埋的假设）
2. 按契约校验：结构 / 引用 / 命名 / 数值可行性
3. 通过 → 实现、跑编译门、提交；不通过 → **把卡片改回 `status: open`，在 answer 里追加退回原因**，Codex 下一轮能看到

## 为什么保留 md 副本，即使 JSON 已经落盘

JSON 只承载**数据**，承载不了「为什么这么设计」。三周后你问"为什么目标定 18 kg 而不是 25 kg"，答案在 md 里，不在 JSON 里。

## 一个提醒

如果它把 `status` 改成了 `done` 但 answer 文件是空的，别信 `done`——**以文件内容为准，不以状态为准**。这是所有基于状态的协议的通病。
