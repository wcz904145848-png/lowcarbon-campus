# 视觉基线：`画风参考图.jpg` 的工程读法

> 这张图是**你给的**，不是设计端的产出。我按工程视角读它，只提取会影响代码和契约的部分；审美判断归 Codex。
> 原图：`30_Art/画风参考图.jpg`（1599×1070，10 个手机竖屏界面拼图）

## 一、它暴露了一个契约冲突（最重要）

参考图是**手机竖屏**，我之前在契约里写的是横屏 `1920x1080`。这不是小事：

- 竖屏 HUD 的按钮在底部拇指区，横屏在右侧
- 竖屏一屏只能放 4–5 个行动项，横屏能放 8 个
- 竖屏的「结算页」是整屏推进，横屏是弹窗

**已处理**：`contract.json` → `ui.resolution.status = pending-platform`，等你确认平台后再定值。
**在确认之前，Codex 的 UI 方案按竖屏出草稿**，我不按横屏实现。

### 最值得抄的一件事

第 3 屏那个「**计算情景（必填）**」：

```
原交通方式：汽车
出行距离：2 km
排放因子：0.20 kg/km
替代方式：步行（0 kg/km）
→ 估算减排 0.40 kg CO₂e
```

**这个设计把"我减排了多少"从魔法数字变成了可验算的过程。** 竞赛评委问"0.4 kg 哪来的"，屏幕上就有答案——而且是玩家自己填的。这一条比任何美术都值钱。

但它需要 `ActionDef` 多三个字段（`baselineMode` / `distanceKm` / `factorKgPerKm`），属于**契约变更**。等平台确认后，我把它并进一张 UI 任务卡一起发，不在 T-001 里夹带。

## 三、我建议砍掉的范围（现在是垂直切片，不是产品）

图上 10 个界面，按 3 分钟演示的标准：

| 界面 | 判断 | 理由 |
|---|---|---|
| 低碳任务列表 | **必做** | 核心交互 |
| 碳减排反馈 | **必做** | 主题表达全靠它 |
| 校园地图 | **必做**（简化成一张静态图 + 3 个热点） | 演示需要"场所感" |
| 结算/共建进度 | **必做**（合并成一个） | 3 分钟要有个收尾 |
| 花园 | 可选，做 1 个格子 + 1 株植物 | 证明养成链路存在即可 |
| 图鉴 | 砍 | 10 个界面的收藏系统 = 两周工作量，演示只看到 3 秒 |
| 盲盒 / 交换 / 好友 | **砍** | 全部需要后端或假装后端，演示时崩一次就完了 |

砍掉的三项正好是我在 `00_BRIEF.md` 里写的红线（不做联网、不做账号）——**图和红线冲突时，红线赢**。

## 四、给 Codex 的三条约束（读到这段时请遵守）

1. 这轮 UI 按**竖屏**出，但锚点用相对描述（"底部 12% 高度区域"），不要给绝对像素——平台没定。
2. 不要设计图鉴/盲盒/交换/好友。它们已经判定为砍。**做减法比做加法难，但这是 3 分钟演示的唯一出路。**
3. 「计算情景」那一屏是重点，把它当成产品的核心界面来设计，而不是提示框。
