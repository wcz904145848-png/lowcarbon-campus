## 项目身份

- 名称：**碳种校园**
- 一句话：基于低碳行为可视化与植物养成机制的校园游戏化交互设计
- 口号：让每一次低碳行动，都长成一片看得见的森林
- 用户：在校大学生
- 场域：教学楼 / 图书馆、宿舍 / 生活区、食堂 / 商业区
- 社交范围：好友、宿舍、班级、学院

## 要解决的三个问题（P2）

1. 行为分散 —— 步行、公交、节电、循环利用散在日常，难集中记录
2. 结果抽象 —— 减排以不可感知的数字存在，缺直观反馈
3. 动力不足 —— 单次奖励易消退，持续参与需要成长目标与社交联系

## 核心机制①：核算（P6）

```
估算减排量 = 基准情景排放量 − 实际情景排放量
出行示例：距离 ×（原交通方式因子 − 实际交通方式因子）
2 km × (0.20 − 0) = 0.40 kg CO₂e
```

- `0.20 kg/km` **仅为演示假设**，不是正式校园核算系数（原文明确标注）
- 数据可靠性边界四步：记录 → 计算 → 反馈（显示来源与置信提示）→ **防重复**

> 这一条已在契约里落成 `tables.FactorDef` + `rules.antiDuplicate` + `rules.estimatedNotReal`。

## 核心机制②：双账户（P7）

```
减排数据层（真实）          游戏表现层（虚拟）
累计估算减排量 12.8 kg  →   虚拟成长值 +128
保留个人累计记录；不因社交交易而转移
```

- 映射：**每 0.1 kg CO₂e → 1 成长点**
- 关键原则：虚拟树木 ≠ 实际固碳；减排量与成长值**分别记录、分别展示**

> 契约里落成 `accounts` 节。这是全项目最重要的一条，工程上必须能被违反检测。

## 设计定位（P5）

一个核算、两层反馈、三类互动：

| 层 | 内容 |
|---|---|
| 可信的行为记录 | 校园任务 → 行为量 → 估算减排量 |
| 可见的树木成长 | 个人树木、植物图鉴、校园公共森林 |
| 有趣的校园互动 | 种子盲盒、互换、好友采集与共建 |

## 用户旅程（P8）

行动 → 核算 → 成长 → 社交 → 共建

> 行为反馈闭环：行动 → 可量化结果 → 植物变化 → 社交鼓励 → 下一次行动

## 三类互动（P9）

| 机制 | 说明 |
|---|---|
| 植物盲盒 | 完成不同类型任务获得主题种子，随机性带来惊喜 |
| 种子交换 | 重复种子在同学/宿舍/社区交换，促进真实关系 |
| 好友采集 | 仅采集可开放的虚拟能量，允许回赠、浇水、互助 |
| 公共花园 | 个人累计贡献推动宿舍/学院虚拟景观恢复 |

**防游戏性盖过环保性**：盲盒不付费；种子交易不改变真实减排记录；采集有上限、可退出。

## 信息架构（P10）

校园绿色账户 → 低碳行动（任务选择/行为登记、因子/审核）/ 低碳账本（日周月趋势、类别分析）/ 虚拟植物（成长、图鉴、盲盒、花园）/ 校园社区（采集、交换、共建、公共森林）

底层：行为记录 → 核算规则 → 双账户 → 可视化反馈

## 可持续性手段（docx）

节气皮肤（24 节气 = 24 赛季）、季节通行证、稀有物种抽卡、养成加速、社交赠礼。

原文自评：**"一旦大规模商业化，低碳环保的概念就会被稀释，应当适当平衡"**。

> 竞赛演示阶段全部不做。记在这里是为了写答辩材料时能引用。

## 理论依据（docx）

- 自我决定理论：自主 / 胜任 / 归属；外在奖励若被感知为"控制性"会削弱内在动机
- 蔡加尼克效应 + 沉没成本：图鉴未集全会一直惦记
- 心流：即时反馈、清晰目标、控制感

## 竞品（P4）

蚂蚁森林（行为→能量→树）、Forest（专注→成长）、JouleBug（挑战→团队→追踪）。
差异化：校园本地化 + 减排结果展示 + 把成长机制从"专注时间"迁移到"低碳数据"。

## ⚠️ 一句要注意的话（P11）

> **课程实现边界：优先使用可点击原型＋模拟行为数据，不要求接入真实校园系统或完成完整软件开发。**

原文的交付预期是 **Figma 可点击原型**，不是完整游戏。现在要做 Unity 可玩版本，属于**超出原课程边界**。

这不影响做，但影响**验收标准**：我们要的不是"功能齐全"，是"3 分钟内把双账户闭环演出来"。所有范围决策都按这条判。
